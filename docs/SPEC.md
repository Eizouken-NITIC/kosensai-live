# 仕様

複数のファイルに跨る決定と、採らなかった案の理由を記述する。単一のファイルで完結する
ものは当該ファイルのコメントに置く。

## ライブコメントを実装しない

配信サイトにライブコメントの機能を持たせない。これはこちらの判断であり、外部からの
禁止事項ではない。Notion での合意は、公式サイト側に配信サイトへのリンクを 1 本置くまでと
すること、および配信サイトを可能な限り簡素に保つことであり、配信サイトの内部構成を
定めるものではない。

実装しない理由は次の 2 点である。

コメントを受け付けると配信サイトが静的配信ではなくなる。現在は Caddy が `web/` を
配信し、HLS を MediaMTX へ中継するだけの構成であり、状態を持つ処理が存在しない。
当日に停止した場合の影響範囲が配信そのものへ及ばない。

学内向けの配信であり、投稿者の特定と不適切な投稿への対処を運用として持てない。

### 拡張の経路

実装しない判断であって、将来の追加を妨げない。追加する場合の経路を次のとおり確保して
ある。

視聴ページ（`app/src/routes/+page.svelte`）の右カラムは、現在は公式サイトの iframe が
1 枚だけである。ここをタブで切り替える形にすればレイアウトを変更せずに追加できる。

`hosts/server/Caddyfile` は `handle_path /hls/*` と静的配信の 2 つの `handle` で
構成されている。`/api/*` の `handle` を追加し、別プロセスへ中継する形にする。
コメントの処理を MediaMTX や Caddy と同じプロセスに置かないことで、その停止が配信の
停止にならない状態を保つ。

## セグメント長と OBS のキーフレーム間隔を一致させる

`hosts/server/mediamtx.yml` の `hlsSegmentDuration` と、`hosts/obs/README.md` が
指定する OBS のキーフレーム間隔は、いずれも 2 秒である。この 2 つは独立に決められない。

HLS のセグメントはキーフレームでのみ分割される。MediaMTX は各セグメントが最低 1 つの
IDR フレームを含むよう長さを調整するため、キーフレーム間隔が `hlsSegmentDuration` より
長い場合、実際のセグメント長はキーフレーム間隔に引き伸ばされる。セグメント長は再生遅延
（プレイヤーはセグメント 3 本分をバッファする）と、視聴開始までの待ち時間の双方を決める。

片方だけを変更した場合、設定値と実際の挙動が一致しなくなる。変更する場合は両方を揃える。
