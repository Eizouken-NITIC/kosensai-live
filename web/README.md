# web — 配信サイト（視聴ページ・サイネージページ）

配信サーバー（`hosts/server/`）の Caddy が `/srv/live` としてマウントし、
そのまま静的配信する成果物。特定のマシンに紐づくものではなく、
**電算部 HP 部門と共同で内容を詰める**ものなので `hosts/` の外に置いてある。

| URL | ファイル |
| --- | --- |
| `https://live.kosensai.ichinoseki.ac.jp/` | `index.html` |
| `https://live.kosensai.ichinoseki.ac.jp/?ch=ch3` | 同上（Ch 直接指定） |
| `https://live.kosensai.ichinoseki.ac.jp/signage/` | `signage/index.html` |

## ファイル

```
web/
├─ index.html            視聴ページ（Ch タブ切替 + 公式サイト iframe）
├─ signage/index.html    サイネージページ（Kiosk 全画面）
├─ config.json           ★ Ch 定義と公式サイト URL の単一の情報源
├─ assets/
│  ├─ theme.css          ⚠️ 暫定テーマ。HP 部門とすり合わせて差し替える
│  ├─ viewer.css         視聴ページのレイアウト
│  ├─ signage.css        サイネージのレイアウト
│  └─ player.js          HLS 再生ロジック（両ページ共通）
└─ vendor/hls.min.js     hls.js 1.6.15（学内完結のためローカルに同梱）
```

## ⚠️ スタイルの扱い

`assets/theme.css` の色・フォント・角丸は **配信班が仮で置いた値**であって、
確定デザインではない。Notion「責務分担 > 共同で進めるもの」の通り、
配信サイトの見た目は HP 部門とすり合わせて決める項目。

そのため:

- **HTML に色・余白を直書きしない。** すべて `theme.css` の CSS 変数を経由する。
- **レイアウト（viewer.css / signage.css）とテーマ（theme.css）を分けてある。**
  すり合わせ後は `theme.css` の `:root` を差し替えるだけで済む。
- HP 側のデザインが出てきたら、まず `theme.css` を置き換えて突き合わせる。

### 決まったこと（2026-08-04）

**ライト基調にする。** 公式サイトを実測してライト基調・キーカラーは青〜シアン系と
分かったため（下記「公式サイトの調査結果」）。視聴ページは公式サイトを iframe で
真横に並べる構成なので、暗い UI だと白いパネルが隣接して浮く。

ただし公式サイトは今 COMING SOON のティザー 1 枚しか無いので、
**ティザーの具体値（`#f5efe6` / `#0d5b6d` 等）は写していない。**
「ライト基調＋青〜シアン系アクセント」という方向性だけ採用した仮値になっている。

映像まわりだけはテーマに依らず暗いままにするため、`--stage-*` トークンに
分けてある（プレイヤーの下地、待機オーバーレイ、サイネージの待機画面）。
UI をライトにしても映像の見え方は変わらない。

### まだ決まっていないこと

- **高専祭のキーカラーの確定値**（`--accent`、現状 `#0e7490` は仮）
- **見出しフォント**（現状は OS 標準の日本語サンセリフのみ。
  公式は見出しに Noto Serif JP を使っている痕跡がある）
- 本番サイト公開後に `:root` を差し替えて追従する

## config.json（単一の情報源）

### channels

ここを直すと以下すべてに反映される。

- 視聴ページのタブ
- サイネージの対象 Ch
- `hosts/obs/srt-urls.sh` が生成する OBS 用 URL
- `hosts/server/scripts/preflight.sh` の突き合わせチェック

`id` は MediaMTX のパス名（`hosts/server/mediamtx.yml` の `paths:`）と
一致していなければならない。preflight がずれを検出する。

**Ch2（第二体育館）は開催有無が未確定。** 無くなったら `config.json` から
1 要素、`mediamtx.yml` から 1 ブロック消すだけでよい。

### officialSite

iframe に出す公式サイトの URL。HTML には直書きせず、ここから差し込んでいる。
**この URL は確実に変わる**ので、変更時はこの 1 箇所だけ直せばよい。

| キー | 用途 |
| --- | --- |
| `embedUrl` | iframe の `src` |
| `homeUrl` | 「公式サイト ↗」リンク先（別タブ） |
| `label` | パネル見出し |

## 公式サイトの調査結果（2026-08-04 時点）

実際に取得して確認した内容。**開催が近づいたら取り直すこと。**

### 埋め込みの成立条件はクリアしている

`https://kosensai.ichinoseki.ac.jp/` にも `/archive/2025/events/` にも
**`X-Frame-Options` / `CSP frame-ancestors` は付いていない**（`curl -sI` で確認）。
iframe 合成は現状のヘッダ構成では成立する。

### ただし今は埋め込む中身が無い

2026 のサイトは **COMING SOON のティザーページのみ**。

| パス | 状態 |
| --- | --- |
| `/events`（タイムテーブル想定） | **404** |
| `/news`（お知らせ想定） | **404** |
| `/archive/2025/events/` | 200（昨年のフル版が残っている） |
| `/archive/2025/news/` | 200 |

昨年と同じ URL 構造なら、開催が近づくと `/events`・`/news` が生えてくる見込み。
**生えたら `officialSite.embedUrl` をそこに向ける。**

### トップページを埋め込み先にしない方がよい理由

- トップページは `h-screen` の全画面演出なので、細い右カラムに入れると窮屈になる
- 昨年のトップページは **約 2.3MB / 46 リクエスト**。100 人が同時に開くと重い。
  一方 `/events`・`/news` の HTML は 5〜7KB（圧縮後）と軽い
- スクロールバーを隠す実装（`hidden-scrollbar`）なので、狭い枠だと
  下にコンテンツがあることに気づかれにくい

### iframe に `allow-scripts` を必ず残すこと

公式サイトは Next.js + Framer Motion で、**要素が `opacity: 0` から始まり
JS のアニメーションが完走して初めて表示される**実装になっている。
グレースフルデグレードしないので、JS を止めると中身が透明のまま何も出ない。

`sandbox` 属性自体は必須ではない（無指定なら制限なしで JS は動く）。
付けているのはハードニング目的で、フレーム側からこちらのページを
別ページに飛ばされないようにするため。

### レイアウト面

- `html` に `overflow-x-hidden` が指定されているので横スクロールバーは出ない
- タイムテーブルは `md:grid-cols-2`（768px 未満で 1 カラム）なので、
  360px 幅でも縦積みリストとして読めるはず
- ナビは 4 リンクを横一列に並べるだけでハンバーガー化しない。狭いとタップ領域が窮屈
- `/archive/2025/map/` は自作のズーム SVG なので狭い枠には不向き

## ローカルで確認する

```bash
python3 -m http.server 8080 --directory web
# http://localhost:8080/          視聴ページ
# http://localhost:8080/signage/  サイネージ
```

`/hls/` が無いので「まだ配信が始まっていないようです」表示になる。
レイアウト・タブ・iframe の確認はこれで足りる。

映像込みで見たい場合は、配信サーバーを立てて `smoke-test.sh` でテストパターンを
流しながらブラウザで開く。

## 設計上の判断

- **hls.js はローカル同梱**（CDN 参照ではない）。学内限定配信なので、
  外部到達性に依存させない。更新は `vendor/hls.min.js` の差し替え。
- **通常 HLS（セグメント 6 秒）がデフォルト。** LL-HLS はリクエスト頻度が
  大きく増えるため、低遅延が本当に必要と判明した場合のみ検討する。
- **画質選択 UI は無し。** MediaMTX はトランスコード／ABR 非対応で 1Ch 1 品質。
- **デフォルトはタブ切替（グリッド同時視聴ではない）。** 全視聴者が 4ch 同時に見ると
  4.5Mbps × 4ch × 100 人 = 1.8Gbps となり LAG 2Gbps の上限に近づく。
- **配信前でも 10 秒ごとに自動リトライ。** 開場前にサイネージ端末を先に起動しておける。
- **公式サイトは iframe で合成**（private→public は Chrome LNA 対象外）。
  コンテンツを複製せずタイムテーブルを同一画面に出せる。
  成立条件は公式サイト側に `X-Frame-Options` / `CSP frame-ancestors` が無いこと。
  → `docs/checklist.md §G` で確認する。**付いていたら iframe は諦めてリンクに切り替える。**
